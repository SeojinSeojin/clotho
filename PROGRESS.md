## Summary of findings

**Core (2026-11-07/08; Gemma replicates every pre-generation finding).**
1. Standard split: Clotho beats MDSA and Lookup (Drain) on every seed (Llama 0.749 / 0.794 @100 / @200; Gemma 0.780 / 0.832), also on held-out systems and against baselines with random reference sets. Template-disjoint split: Clotho ties MDSA, every lookup is at chance.
2. Leakage: the original Clotho protocol computes labels and post-generation scores from the same 10 generations; net leakage +0.125 / +0.132 AUC for output entropy, +0.067 / +0.070 LOHSvar. Leak-free output entropy still beats Clotho @100 and ties @200; it needs 4 samples to match Clotho @100 (2.4x Clotho's batched HF cost, 8.3x a vLLM prefill, 36x online; Gemma 1.5x / 6.9x / 22x).
3. Failures are template-level: 95-99% of the reliable pass-rate variance lies between templates; within-template AUC is near chance against the 5-sample label but rises for Clotho from 0.555 to 0.609 against a clean 40-sample label (ceiling 0.698).
4. Natural distribution (uniform raw lines): Lookup (Drain) ties Clotho (Llama -0.006 / -0.016) or beats it (Gemma -0.037 / -0.057, every seed); Clotho beats output entropy by about 0.04-0.11.
5. Cross-system (one source system): Clotho 0.62-0.64, level with MDSA, lookups at chance.

## Decisions (still in force)

**Task, scorer, systems (2026-11-07).** Scorer `strict_match` (text after the last `Template:` line equals the Loghub-2.0 `EventTemplate` exactly; parse failure = fail), template `rules_template` (states the Loghub convention: one `<*>` per whole variable token), no lenient extensions, no few-shot. Chosen as the least lenient scorer with input PASS in 20-80% on most systems; in 40 inspected failures most were real model errors. Systems outside 10-90% PASS are dropped: Proxifier (0%) for both models, Apache (94.4%) for Gemma. Mac (12%) and HPC (18%) are kept.

**Clotho harness (2026-11-07).** `log_parsing_phase3_lib` seeds both `np.random` and the reference extension (the core runner does not); `clotho_run(method="balanced")` reproduces `rci.simulate_iterations` exactly on the standard split. Layer tuning (HDFS, Spark, Linux; fixed before results): Llama 16, Gemma 21. GMMb = the paper's GMM_base (`SA(mode="MLSA")`). Drain lookup = logparser3 Drain with the Loghub-2.0 benchmark settings; Lookup (Drain, default) = drain3 defaults; hybrid = Drain lookup if the test input's Drain group is in the reference set, else Clotho. Splits: standard (Clotho's protocol) and template-disjoint (HPC disjoint skipped under the old label). Post-generation pass (`log_parsing_postgen.py`): Tok-Prob/Tok-Ent use the correct prompt length (`*_paper` columns reproduce the repo helper's off-by-one), LOHSvar layer 23 (Gemma 28), Sem-Ent with DeBERTa in bf16.

**Protocol choices (2026-11-08).** The original-protocol leakage is answered from upstream code (`coinse/clotho` @e8aed3d). Baseline fairness: baselines also scored with random reference sets on T' = Clotho's test set minus those references. Cost = offline batch cost per test input (Clotho = batched HF forward pass to the fair layer + CPU scoring; output entropy = vLLM with all prompts at once); this understates Clotho's advantage. Cross-system Drain lookup uses each system's own Drain run. Natural suites: 500 lines drawn uniformly from all Loghub-2.0 lines of the system not in its suite (no dedup, seed 4242), not registered in `supported_datasets`; systems with < 15 PASS or FAIL are skipped. **E, cached parser with human review (2026-11-10; fixed before results, `log_parsing_cached_review.py`).**
- Stream: per system, Loghub-2.0 `<Sys>_full.log_structured.csv` lines 1-50,000 in original order (all lines if fewer). Systems = each model's kept systems (Llama 13, Gemma 12).
- Cache: logparser3 Drain with the Loghub-2.0 settings over the stream (`log_parsing_drain.LH2`); group = Drain cluster (lines are never reassigned, so this is the online assignment). The cluster's first line goes to the LLM (rules_template, greedy, vLLM, max 512 tokens); its parsed template (parse failure = empty) is the group's cached template. HF hidden state of that prompt (last prompt token) at the fair layer and at D's tuned layer (Llama 24, Gemma 35).
- Drain fix (decided on grouping alone, before any LLM output): logparser3 / Loghub-2.0 Drain never attaches the cluster of a message shorter than the tree depth, so every identical later line opened a new group (HealthApp 6,867 singleton groups, Linux, Mac). `log_parsing_stream.py` attaches it at the leaf the search reaches. Remaining over-splitting is Drain's own (HealthApp one-token messages with digits, OpenStack UUIDs under the `\d+` regex) and is kept.
- Correct: a line is correct iff its group's cached template equals its ground-truth EventTemplate (strict). PA over all stream lines.
- Review: retrospective, after the stream. One action = one group; the reviewer sets the group's template to its most frequent ground-truth template (ties: first seen), which is the best a single template can do, so gain = lines with that template minus lines matching the cached one (Drain grouping errors stay). The reviewer also learns whether the first line's output was correct (label for online refits). PA at N = 0, 5, 10, 20, 50, 100 reviews (fewer if fewer groups). Reported: share of mis-parsed lines fixed = (PA_N - PA_0) / (1 - PA_0), macro mean over systems (systems with PA_0 = 1 skipped); lines fixed per review.
- Orderings (risk scores are multiplied by group size = lines in the stream, except Random / Newest / Most frequent / Oracle): Random (seeds 0-4); Most frequent; Newest (creation order, last first); LLMLog confidence C (`log_parsing_llmlog.confidence` on the greedy output: mean token probability of the whole output + word consistency, a = 0.3); Output entropy (10 extra samples per first line, T 0.8, engine seed 1, entropy of parsed templates as `log_parsing_phase3_final._entropy`); Ours = D: the protocol-chosen source model and hyperparameters of Experiment D (Llama MLP h128 alpha 1e-4 on PCA32 of per-system z-scored layer-24 states, refit weight 100; Gemma probe + generic features C 0.01, PCA128, layer 35, weight 10), trained on the capped suites of all other kept systems with their main labels, zero target labels; target z-score and PCA fitted label-free on the stream's first-call states; after each batch of 5 reviews refit with the reviewed groups (label = first line correct) repeated w times; risk = 1 - P(PASS); seeds 0-4. Ours (Clotho) = rank average of the D risk and within-stream Clotho (fair layer, fitted on the reviewed groups + 10 initial tests via `log_parsing_strategy.clotho_given_order`), D alone while Clotho cannot fit. Oracle = groups by gain, descending.
- Ours (active + lookup) (user request, finding 11): the first batch of 5 is chosen by D at zero labels (risk x size); after that each batch is ranked by lookup risk x size, where lookup risk = (wrong reviewed groups in the family + D risk) / (reviewed groups in the family + 1), family = cluster of the group's first line in a second, coarser Drain run over the stream (same regex and depth, st halved), and D is refit online as above. With no reviewed group in its family a group keeps its D risk.
- AdaParser: the ported corrector (`log_parsing_adaparser`, greedy) applied automatically to every new cached template; then every ordering is rerun on top of the corrected cache and the best non-oracle ordering at 20 reviews is reported (chosen after the fact, all are listed).

**TRIAGE and E1-E5 (2026-11-10, user request superseding E; fixed before results). Simulation as in E above; module `experiments/triage/`, driver `experiments/log_parsing_triage.py`.**
- TRIAGE API: `Triage(prior, H_first, sizes)`; `queue(b)` -> next b group ids; `update(verdicts)`; `add_groups(...)` for new groups mid-stream. Prior = D's source model (E entry). State: risk r = 1 - P(PASS) from the prior refit on the verdicts so far (weight w). Priority = r x lines of the group so far. Selection per batch of b = 5: candidates = top M by priority; floor(b/2) by uncertainty (largest binary entropy of P(PASS), Clotho's uncertainty half), the rest by greedy max-min Euclidean distance to the reviewed + already picked groups in the prior's PCA space (Clotho's diversity half); candidates ranked by priority to break ties and fill. M tuned in {10, 20, 40} on HDFS, Spark, Linux (mean share fixed at 20 reviews, both models separately, seeds 0-4); the other systems are reported as held-out.
- Propagation: a verdict and the correction apply to the whole Drain group. Ablations (one at a time): no prior (risk from a logistic probe on the stream's own verdicts, PCA as the prior's, constant 0.5 until 2 verdicts of each class); no active selection (top b by priority); no propagation (the correction applies only to lines whose text equals the reviewed first line; verdict still used for refits); no frequency weighting (priority = r).
- E1 orderings: Random; Most frequent; Newest; LLMLog confidence x size; Output entropy x size (extra row); Clotho alone (reviews follow Clotho's balanced reference extension at the fair layer: diversity until a GMM fits on the reviewed groups + 10 initial tests, then half uncertainty half diversity; `log_parsing_phase3_lib._extend_balanced`); D x size (= TRIAGE without active selection); Ours (active + lookup) (E entry); TRIAGE; AdaParser corrector then every ordering on top (best at 20 reported); Oracle. Retrospective reviews at the stream end (sizes = whole stretch).
- E3: N = 1..10 lines fixed and share fixed: prior alone (D risk, no size), prior x size, Most frequent.
- E4 drift: half the budget at the stream midpoint (only groups and lines seen so far; sizes so far), half at the end (refit model carries over). Metric: share of mis-parsed lines fixed among lines of groups first seen in the second half, and over all lines, at N = 10, 20, 50, 100.
- Statistics: per ordering, mean ± std over seeds 0-4 of the macro mean over systems; seeds keeping the sign of the paired difference; SK-ESD and A12 over (system, seed) as `log_parsing_stats`. Deterministic orderings repeat across seeds.
- Cost: wall-clock per new template: TRIAGE scoring and refit (CPU) plus the hidden-state forward pass measured on its own (free when the parser's prefill exposes it); AdaParser corrector vLLM wall-clock per template.
- E5 (fixed after inspecting which files exist, before computing any number): Clotho Zenodo record 19693236 `data.tar.gz`, Llama, the 8 paper tasks and suites (`RQ/analysis_utils.target_testsuites`). Per-sample correctness from `task2labeler` (as `get_test_results`). The paper (RQ3-1) correlates each post-generation metric with the 10-sample test score (Spearman); Tok-Prob (`average_log_probs`) and Tok-Ent (`average_entropy`) use inference 0 only; answer entropy uses all 10. Leaky = paper protocol. Leak-free, seeds 0-4: a seeded permutation of the 10 samples, label half = 5 samples (test score = their pass rate; AUC label PASS if >= 3 of 5), score half = the other 5 (Tok-Prob / Tok-Ent: the first sample of the score half, as the paper uses one sample; also the mean over the score half; answer entropy: entropy of the parsed answers of the score half, where the labeler returns them). Pre-generation control (no output leakage, measures label-noise shift only): the stored input-hidden-state MDSA score (`input_hidden_states_dist_score.pkl`, the paper's layer and reference size closest to 150, seed 0).
